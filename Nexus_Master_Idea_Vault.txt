NEXUS — MASTER IDEA VAULT
========================================
Purpose:
A complete inventory of Nexus ideas, concepts, capabilities, design directions,
principles, and future possibilities collected so far.

IMPORTANT:
- This is an IDEA VAULT, not the implementation roadmap.
- Nothing here is automatically approved, required, or currently implemented.
- Ideas are intentionally preserved so we do not lose ambitious possibilities.
- Later, each idea can be classified as: BUILD NOW / BUILD LATER / EXPERIMENT /
  OPTIONAL / EXTERNAL TOOL / CUT.
- "User Ideas" are the original ideas/features raised by Rai.
- "Our Evolved Ideas" are concepts synthesized, refined, or expanded during
  later architecture/product discussions.
- Claude's useful additions are included inside the synthesized section where
  they materially improved the Nexus concept.

PART III — OUR EVOLVED / SYNTHESIZED NEXUS CONCEPTS
============================================================

A. CORE DEFINITION
------------------
1. Nexus as a "Personal Intelligence System".
2. Nexus as a "Personal Context-and-Action System".
3. Nexus as a "Personal Intelligence + Orchestration System".
4. Final evolved direction:
   Nexus should understand the user's context, coordinate capabilities/tools,
   remember appropriately, verify outcomes, reduce mistakes, and help the user
   act across digital life while keeping the user in control.
5. "Second mind" remains a product metaphor rather than a literal architecture.
6. JARVIS/FRIDAY/ULTRON are experience inspirations, not engineering specs.
7. Nexus should be broader than any one capability.
8. Nexus should not try to be the world's best specialist at everything.
9. Nexus should be the layer that can orchestrate the best specialist tools/providers.

B. PERSONAL CONTEXT
-------------------
10. Personal context should be a core differentiator.
11. Understand projects, files, tasks, goals, decisions, preferences, people,
    relationships, deadlines, previous actions, and relevant history.
12. Context should be structured enough to reuse but not an enormous graph unless
    the value justifies it.
13. Context should be portable across AI providers.
14. Context should be scoped by project/task/session where useful.
15. Context should include constraints and user preferences.
16. Context should be able to distinguish current vs stale information.

C. BRIEFING DESK / CONTEXT BROKER
---------------------------------
17. Use a "brief" before asking a model/tool to act.
18. A brief can contain:
    - user request
    - relevant file excerpts
    - source/page references
    - user preferences
    - past decisions
    - task/project constraints
    - previous relevant results
19. Models/providers can consume the same portable brief.
20. After an action, a "debrief" can record:
    - what was asked
    - what happened
    - what was accepted/rejected
    - evidence/results
21. Brief/debrief can become a provider-independent layer.
22. The goal is to stop re-explaining the user's world to every AI.

D. "TRUSTED STATE WITH RECEIPTS"
-------------------------------
23. Nexus should know what exists.
24. Nexus should know where it came from.
25. Nexus should know its version.
26. Nexus should know whether it was processed.
27. Nexus should know whether an action actually succeeded.
28. Nexus should preserve evidence/receipts.
29. Important actions should produce an action receipt:
    - intended action
    - actual action
    - expected result
    - verified result
    - source/evidence
30. Generic AI can answer; Nexus should additionally maintain trusted state.

E. HUMAN-ERROR REDUCTION
------------------------
31. Human-error reduction is a major product principle.
32. Detect duplicates.
33. Detect version conflicts.
34. Detect stale information.
35. Detect contradictory deadlines.
36. Detect wrong destinations.
37. Detect missing requirements.
38. Detect incomplete tasks.
39. Detect repeated user mistakes.
40. Detect repeated Nexus mistakes.
41. Detect tool-success vs real-task failure.
42. Detect accidental destructive actions.
43. Detect duplicate reminders/tasks/notes.
44. Use deterministic checks wherever possible.
45. Do not promise "AI error elimination"; only detect/verify what is actually
    checkable.
46. Record false positives and false alarms to improve the system.
